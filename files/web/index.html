拨号开关
          
          
            总闸：关掉后四种拨号方式一个都不拨（对所有模组生效）。
            
• 自动组网：整台模组跳过 —— 不激活 PDP、不拉主机侧拨号器、不建 WAN 接口；
            
• 主机侧拨号器（QMI 的 quectel-CM / fibocom-dial / meig-cm / simcom-cm）：立刻停掉（数据链路随之断）；
            
• 手动「拨号」/「重拨」：直接拒并说明原因，不下发任何 AT；
            
• 写 APN 时的自动激活（「高级配置 → 参数设置」）：也只写配置，不激活 PDP。
            
已经建过的 WAN 接口不动（只是拿不到地址）；要拆接口自己去网络设置里删。
            
这个是全局开关，写回配置文件（[net] dial_enabled，重启不丢）；
            关掉不影响 AT / 短信 / 信号 / 注册，也不影响模块侧的其他功能。
          
        

        
      

      
拨号已开启：自动组网与手动拨号都会按模组类型各自的方式拨号

    

    

      
模块总线类型
          
          
            先看模组接在哪种总线上，因为它决定了 AT 口怎么开、谁来拨号：
            
• USB：AT 口是 /dev/ttyUSB* / COMx，类型取值见下。
            
• PCIe（MHI / wwan）：AT 口是字符设备（/dev/mhi_DUN、/dev/wwan0at0），
            不跑 termios；数据面要么是 mhi_netdev/rmnet 交出来的 wwan0（QMI，由厂商拨号器拨，
            它自己会认 MHI），要么是 MBIM（/dev/wwan0mbim0，由 modemd 拉起的 quectel-CM 拨）。
            卡死时可以在下面直接做 PCIe 软复位（remove + rescan，不断电）。
            
USB 类型决定谁来拨号：0 QMI/NDIS 与 2 MBIM 要靠主机侧拨号器
            （QMI 用本包自带的厂商拨号器：移远 quectel-CM、广和通 fibocom-dial、
            美格 meig-cm、芯讯通 simcom-cm，按模组厂商自动挑；
            MBIM 一律用 quectel-CM —— 四家里只有它实现了 MBIM，而它认 MBIM 靠的是
            标准 USB CDC 描述符，与厂商无关）；1 ECM、3 RNDIS、5 NCM 只要模组把 PDP 激活、
            主机对网卡跑 DHCP 就能上网。
            
下面的「拨号」按类型只走一种方式：0 QMI 与 2 MBIM 由 modemd 让出模组侧数据承载、
            再拉起主机侧拨号器（不做 AT+CGACT —— 否则两边抢模组唯一的数据承载，
            拨号器会被模组拒：QMI 报 QMUXError，MBIM 报 MBIM_CID_CONNECT Status=2）；
            1/3/5 ECM/RNDIS/NCM 才做模组侧这一段
            （AT+CGDCONT → AT+CGACT=1,<cid> → AT+CGPADDR）。
            非 OpenWrt（或关掉 [net] host_dial）时，QMI 会提示你在主机侧自行运行那个拨号器
            （就是上面的「主机侧还要做」）。
            
没读过 USB 网卡模式的模组（广和通 / 芯讯通）会退回读 USB 描述符的接口类码：
            协议写在控制口（class 02）的子类上 —— 02/0d NCM、02/0e MBIM、
            02/06 ECM、ef/04 RNDIS；0a 是 ECM / NCM / MBIM
            共用的数据口（光看它认不出协议）；全是 ff 就按 QMI/NDIS 处理。
            两边都拿不到就是「未知」。

拨号
          
          
            过程可追溯：拨号会逐步记录（模组侧：写入 APN → 激活 PDP → 回读确认 → 读本机地址 → 找主机侧网卡；
            QMI：写入 APN → 释放模组侧承载 → 拉起主机侧拨号器 → 找主机侧网卡），失败时卡在哪一步一目了然。
            
「断开」只停数据面：QMI 停主机侧拨号器；其余类型发 AT+CGACT=0,<cid>。
            AT 口、短信、注册状态都不受影响；
            内部上下文（IMS / sos）部分固件不允许手动停用，会如实报错。
            
地址读不到不算失败：链路可能还在协商，过几秒点「刷新状态」即可（周期推送也会自动补上）。
            
⚠️ 实测部分固件（FM350-GL）停用后会把这个 cid 从配置列表里抹掉，所以
            「断开 → 拨号（APN 留空）」时后端会用上次用过的 APN 补写一次配置再激活（步骤里会写明补了什么）。
            
路由器（OpenWrt）上还会自动组网：模组一上线就自动拨号，再按这台模组的 USB 类型
            建对应的 WAN 接口（模式 1/3 下 qmi / ecm / ncm / rndis / mbim 都用 modem_pro ——
            一张接口跑 v4+v6，「网络 → 接口」里看得到 IP；QMI / MBIM 的数据呼叫
            还由 modemd 自己托管的拨号器拉起来，不是 uqmi 那套「QMI 蜂窝」）并加入防火墙，
            插上就能上网；同名接口已存在则保持不动。
            结果就在下面那行「自动组网（WAN 接口）」与「主机侧拨号器」里。
            
模组的 PDP 是 IPV4V6 / IPV6（或地址里有 IPv6）时，
            dhcp 模式还会再建一张 IPv6 兄弟接口（modem0_6，proto=dhcpv6）并打开该网卡的
            accept_ra —— 模组的 IPv6 多半是随 RA（SLAAC）下来的，不打开它就只有 link-local
            （OpenWrt 默认 accept_ra=0，而路由器又在转发）；
            modem_pro 模式下一张就够，不再建兄弟接口。
            
★ 模组给的是「on-link 的 RA /64」而不是前缀委派（PD），而这个 /64 又被原样交给了内网，
            所以公网回包时上游要在模组链路上找内网设备 —— 那一环靠 modemd 自动配的
            route6 modemd_lan6route（低 metric）与 odhcpd 的 NDP relay（dhcp.lan.ndp=relay），
            ECM / NCM / RNDIS / MBIM 都要（QMI 不需要）。
            
            右上角那个「IPv6」开关（[net] wan_ipv6，默认开）可以整体关掉模组侧 IPv6。

定时任务

        
          
          
        
      

      

      

    


    

      
说明

      
    
        
  • 一个时间点可以带多个动作，按顺序依次下发：
          「同时锁频段 + 锁基站」就加两个动作（例如 08:00 锁频段 NR 78 → 锁基站 NR 627264/PCI 521），
          22:00 解除锁基站 → 解除锁频段。建议先锁频段再锁基站（反了可能要求锁到已被排除的频段上）。
          一个动作失败不影响后面的，失败原因会写进「上次结果」。
    • 
        
  • 一条任务有两个时间点：到「开始时间」执行开始动作组，到「结束时间」执行结束动作组。
          结束时间可以留空，那就只执行一次（结束动作组不会生效）。
    • 
        
  • 时间按本机时区判定；「生效星期」不选 = 每天都跑；跨天时段直接写两个时间即可（开始 23:00 / 结束 07:00）。
    • 
        
  • 到点后 15 分钟内都允许补做（进程重启、串口忙也不漏），但超过窗口不会补跑历史槽位 ——
          免得关机一天后开机就把昨天的动作全做一遍。同一时间点只执行一次（记录随列表一起落盘）。
    • 
        
  • 任务保存在配置文件同目录的 schedule.json（重启不丢），记录目标模组用端口
          （port:COM32）—— 实测本机两块模组 IMEI 相同，用 IMEI 会串台；换 USB 口后按唯一 IMEI 自动迁移。
    • 
        
  • 动作全部复用「锁频段 / 锁基站」页的同一条指令，不会另发未验证的命令；
          模组固件不支持锁网时列表会标「机型不支持」并在执行前拦下（到「锁频段 / 锁基站」页点「探测固件支持」可核对）。
    • 
        
  • 定时器不看有没有人开页面：到点一定执行（和流量配额一样是后台循环）。

        APN 走标准 AT+CGDCONT=<cid>,"<PDP类型>","<APN>"，写完会回读确认
        （模组回 OK 不代表真的存下了）。
        ✅ 写完会自动把该 cid 重新激活（AT+CGACT=0,<cid> 再 AT+CGACT=1,<cid>），
        并顺手激活 IMS 上下文（APN = ims，一般 cid 1）—— 不用再去点「重新激活」；
        IMS 那一步失败不影响写入（有些固件不许手动激活 IMS）。
        也可以用上下文表里的「重新激活」手动再来一次；「停用 / 激活」是直接发 AT+CGACT
        （断开 / 建立该链路）。这些操作都会回读 AT+CGACT? 确认（激活是异步的，最多等约 4 秒）。
        APN 只允许字母/数字与 . - _（逗号与引号会破坏 AT 指令语法，已拦下）；
        上下文表里的「删除」会删掉该 cid 的整条 APN 配置（AT+CGDCONT=<cid>，只给 cid 即删除，
        删完回读确认）—— 已激活的 cid 要先「停用」再删，免得删配置时链路状态不明；
        部分固件不支持删除，会如实报错。
        IMS / sos 这类内部专用上下文不是上网用的，可以改但一般不需要动 ——
        它们也有「激活 / 重新激活」按钮（有些模组出厂时 IMS 未激活，不给手动启动就一直起不来）；
        只是部分固件不允许手动停用内部上下文（实测 RM502Q-GL 的 AT+CGACT=0,2 回 ERROR，
        它的 ims 是 cid 2），所以「重新激活」里的断开是尽力而为：被拒也会继续去激活，最终结果以回读为准。
        

        选网方式 走 AT+COPS：自动 = AT+COPS=0，
        手动 = AT+COPS=1,2,"<PLMN>"。手动选网会重新选网（可能短暂断网）且不会自动回退，
        要恢复传自动即可。漫游偏好等厂商私有参数固件差异太大（本固件 AT+QNWPREFCFG="roam_pref"
        只回一个 255、语义无法确认），不在这里暴露，需要时去「AT 指令」菜单直接发；
        「要不要在漫游时用数据」用上面那张「数据漫游」卡片（不发厂商指令，见那儿的「?」说明）。
      

    


    
    

      
数据漫游
          
          
            语义同手机上的「数据漫游」：关掉后国际漫游时不使用数据。
            
⭐ 本地卡不受影响：本地网注册，以及国内运营商之间的同国异网漫游
            （模组也会报 <stat>=5，但流量与本地资费一样）都照常上网；
            
• 只有国际漫游（卡归属 MCC ≠ 注册网 MCC：国外卡漫游到境内 / 境内卡出国）
            才受这个开关影响：关掉后自动组网不再拨号（不激活 PDP、不建 WAN 接口），
            主机侧拨号器（quectel-CM / fibocom-dial / meig-cm / simcom-cm）立刻停掉；
            
• 判据 = 注册状态 + 卡归属（IMSI 前 3 位），不与模组厂商指令打交道 ⇒ 所有模组都支持；
            「概览 → 信号」里那行漫游状态用的是同一份判据；
            
• 判不出国别（读不到 IMSI / PLMN）时不拦：宁可该拦没拦，也不误断本地卡；
            
• 写回配置文件（[net] allow_roaming，重启不丢）；恢复"允许"后 ≤15 秒重新拉起。
            
⚠️ 不给模组发任何 AT：AT 侧没有标准的漫游开关，各家私有写法
            （AT^SYSCFGEX 的漫游字段取值 0/1/2 都有人用、AT+QNWPREFCFG="roam_pref"
            回 255 语义不明）互相矛盾 —— 猜一个写下去可能把注册与服务域改坏，宁可不做。

        —— 只断数据面，AT 口、短信、注册状态都不受影响，点「本周期不再限制」或下一个周期开始会自动恢复；
        模组如果自己重新拨号，会每 30 秒把它再断一次。要更彻底可以选 关闭射频（AT+CFUN=4，
        飞行模式：连短信一起停，恢复得手动点解除或等下个周期）。
        
⚠️ 展锐 SIPC 那一族（中兴 F50 / UMS9620）不给选「关闭射频」：这类设备整机只有模组这一路上行，
        关了射频会把它自己的管理页 / SSH / 内网通道一起断掉（后端会直接报错），请用「停用数据连接」或「只提醒」。
        
⚠️ 这台模组实测 AT+CGACT? 会同时报 cid 1（上网）与 cid 2（IMS）都激活，
        但 cid 2 属内部上下文、禁止停用（会回 ERROR）——所以只对上网上下文下手，跳过 IMS/sos。
        
统计指令都是厂商私有：未声明该能力的模组这里会显示“不支持计量”，配额无法启用。
        
广和通（FM160/FM650）只报瞬时速率、没有累计计数器：速度是实测的，但“累计”与配额用量由本地积分估算（界面标“估算”）。
        “不自动重置”适合自定义套餐：只累计不归零，对账后手动点「清零并开始新周期」。
        达到上限后自动断网；新周期开始（用量归零）时自动恢复联网。
      

    

    


    

    

      
USB 网卡模式

        
        
      

      

        
        
        
        
      

      

        USB 网卡模式决定模块以哪种协议把上网能力交给主板 / 电脑。
        各家指令、取值都不同（不是都走 AT+QCFG="usbnet"）：
        移远 QCFG "usbnet"、广和通 AT+GTUSBMODE、芯讯通 AT+CUSBCFG（旧款 4G 用 AT$MYCONFIG）、
        高新兴 AT+ZSWITCH、富士康 AT[!^]USBSWITCH、Sierra AT!USBCOMP、华为/巴龙 AT^SETMODE 等。
        取值与指令都取自模块清单（modem_catalog.json 的 usb_at，数据源 Modem-Pro）：
        下拉只列本型号取证过的档位，选一项时下方会显示这一档实际会发的指令（鼠标悬停也能看）。
        清单里没取证参数的型号（如 Quectel RG801、SIMCom 展锐档、有方 N510M）只读，不会猜参数下发。
        改完必须重启模组才生效；重启会让 AT 口短暂断开、USB 可能重新枚举（换 COM 口号时点「刷新模组」重新识别）。

最近插拔事件

      


      

        周期巡检（server.scan_interval，> 0 时生效）每轮都会在扫串口之前跑一遍 USB 层：
        枚举“像模组”的 USB 设备（VID/PID 比对已知表）→ 记插入 / 拔出事件 →
        对“插上了却没有串口”的已知模组，在 Linux / OpenWrt 上自动
        modprobe option 并写 /sys/bus/usb-serial/drivers/option1/new_id 把
        /dev/ttyUSB* 变出来，交给原有的“分组 + AT 探测”找 AT 口。

        ⚠️ 拔出时会在这里记一条事件（带厂商 / 型号 / 模组 id），对应的模组会被关掉
        （线程、缓存、推送都随之清掉）——这就是“知道是哪台被拔了”。

        ⚠️ Windows 的串口由驱动 inf 决定，程序不做自动绑定（设备管理器里带黄叹号时先装厂商驱动）。
      

    

    


    

    

      
PCIe 模组（MHI / wwan）

        
          
          
        
      

      
加载中…

      

      

        PCIe 模组不在 USB 总线上：AT 口是字符设备（/dev/mhi_DUN、/dev/wwan0at0），
        主机侧网卡由 mhi_netdev / rmnet 交出来，没有“拔插”这回事。
        所以这里只管三件事：看得出哪块卡在、绑没绑驱动、一键软复位（remove + rescan，
        不断模组的电，救固件卡死）、手动绑驱动（mhi_pci_generic / mtk_t7xx 没自动认领时）。
        AT 口探测、拨号、自动组网与 USB 模组走同一套流程（发现时会自动把候选 AT 口一起探）。

        ⚠️ 驱动不绑上就不会有 /dev/mhi_*、也不会有 wwan 口 —— 先装 kmod-mhi-pci-generic
        （联发科是 kmod-mtk-t7xx），或在下面点「绑定驱动」。

        ⚠️ 卡死自动恢复：一个 AT 口都找不到超过 150 秒时，程序会先试 USB 软重插；
        场上没有 USB 模组时改对 PCIe 模组做一次软复位（最多 3 次，之后只告警）。
